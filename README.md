# 城市地下管网巡检养护管理系统

面向城市地下管线登记建档、巡检任务、缺陷记录、外出维修、修复验收与设施档案全流程的地下管网巡检养护管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `underground-pipeline-inspection:entries` 这一项，或调用 `resetModule(模块)`。

## 汛前调度桌（运营概览内）

运营概览页带「汛前调度桌」页签，按责任网格（行）× 小时刻度（08:00-20:00，列）铺开
管线、巡检、缺陷、泵站、应急五类事项，异常事项红色标记。

- **拖动改派留痕**：把事项卡拖到另一个网格/小时格，必须填写改派依据；前后责任人、操作值班人、
  时间全部记入改派台账。锁定前是「待提交」虚影，发起人可撤回；同一事项重复拖动会自动作废旧改派。
- **格子锁与冲突**：每格「锁定提交」是一次事务，先锁定者得格（绿色），改派随锁生效；
  他人的待提交改派在该格显示红色「冲突」，只能撤回自己的改派。任何一步写入失败（可用页头
  「模拟下一次写入失败」开关验证），本次锁定整体回滚、不生效。
- **交班确认单**：交班不直接覆盖，先汇总已锁定格子生成「待接班确认单」，必须由交班人之外的
  值班人（右上角切换，也可开两个浏览器标签页实时抢格）确认。
- **两批待办**：接班确认通过后，缺陷类待办只下发到「缺陷记录」页，泵站类待办只下发到
  「泵站运行」页，两批互不混杂。
- **历史快照**：确认瞬间生成只读快照（事项位置、责任人、改派依据），之后排班再怎么变都不影响；
  已交班冻结格与待确认期间的排班拒绝一切改派——新规则只作用于尚未锁定的网格。

调度桌数据单独持久化在 `underground-pipeline-inspection:dispatch`，页内「重置调度桌示例」可还原。
